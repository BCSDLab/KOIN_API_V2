# 검색어 IP 집계 복구 절차

## 배포 후 처리

수정된 API는 전달 헤더의 첫 주소를 IPv4/IPv6 형식으로 검사하여 저장한다. 헤더의 첫 주소를 해석할 수 없으면 요청의 접속 주소로 대체한다. 헤더 우선순위는 유지하며, 프록시 인증이나 XFF 위조 방지를 추가하는 변경은 아니다.

기존 Redis의 `search:count:ip:*` 키는 다음 동기화에서 처리한다. 현재 스케줄은 서버 시간 기준 매 6시간 정각이다.

| 기존 키의 IP 부분 | 처리 |
| --- | --- |
| `203.0.113.20` | 기존 방식으로 집계 |
| `203.0.113.20, 10.0.0.12` | 첫 주소를 추출해 등록된 검색어의 DB 집계에 합산 |
| 긴 IPv6 주소 뒤에 프록시 주소가 붙은 목록 | 첫 IPv6 주소를 추출해 집계 |
| `unknown`, 호스트명, 잘못된 주소 | DB 저장 대상에서 제외하고 Redis 원본을 보존 |

정상 처리한 IP 키는 DB 트랜잭션이 커밋된 뒤에 정리한다. 인기 검색어 ZSET이 비어 있어도 남은 IP 집계를 확인하며, 전체 IP 키를 다시 조회해 일괄 삭제하지 않는다. 해석할 수 없는 IP는 개수만 경고 로그로 남긴다.

## 기존 값 확인

아래 명령은 대상 환경에 평소 사용하는 접속 옵션으로 연결한 `redis-cli`에서 실행하는 예시다. 실제 운영 Redis에는 이 문서 작성 과정에서 접속하거나 명령을 실행하지 않았다.

```bash
redis-cli --scan --pattern 'search:count:ip:*'
```

`--scan`은 SCAN 커서를 순회한다. 결과에는 IP가 포함되므로 공개 로그나 PR에 원문을 붙이지 않는다. 특정 키는 정확한 이름을 복사해 타입과 내용을 확인한다. 다음 주소는 설명용 예시다.

```bash
redis-cli TYPE 'search:count:ip:unknown, 10.0.0.12'
redis-cli HGETALL 'search:count:ip:unknown, 10.0.0.12'
```

정상 IP로 시작하는 목록은 수정 코드로 복구할 수 있으므로 수동으로 삭제하지 않고 동기화 결과를 확인한다. 동기화 오류 로그가 사라졌는지와 해당 원본 키가 정리됐는지를 함께 확인한다. 키가 없어졌다는 사실만으로 운영 DB 반영을 단정하지 않는다.

## 해석할 수 없는 값의 수동 격리

첫 주소 자체가 잘못된 키는 자동으로 삭제하지 않는다. 원본과 검색 횟수를 확인한 뒤, 분석 대상으로 남길 키만 동기화 대상 밖으로 옮길 수 있다.

다음은 **standalone Redis**에서 정확한 한 키를 옮기는 예시다. Redis Cluster에서는 원본과 대상 키의 hash slot이 같아야 하므로 이 접두사 변경 예시를 그대로 사용하지 않는다.

```bash
redis-cli RENAMENX \
  'search:count:ip:unknown, 10.0.0.12' \
  'search:count:invalid-ip:unknown, 10.0.0.12'
```

- 결과 `1`: 원본 데이터와 남은 TTL을 유지한 채 이동했다. 별도 영구 백업을 만든 것은 아니다.
- 결과 `0`: 대상 키가 이미 존재해 이동하지 않았다. 두 키를 비교한 뒤 처리하며 덮어쓰지 않는다.
- 원본 없음 오류: 원본 상태를 다시 확인한다.

격리한 키의 보관·삭제 여부는 내용을 검토한 뒤 별도로 결정한다. 검색 집계 외의 키를 지우거나 Redis 전체를 초기화할 필요는 없다.

## 확인 범위와 남은 한계

- 2026-11-07에 제공된 stage·production 조회 결과에서 `ip_address`가 모두 `VARCHAR(45) NOT NULL`, `utf8mb4_0900_ai_ci`인 것을 확인했다. 이번 변경에 DB 스키마 확대는 필요하지 않다.
- 제공된 stage nginx 설정은 XFF 뒤에 접속 IP를 추가한다. 실제 실패한 Redis 키와 Worker 요청의 실제 전달 헤더는 별도 확인 대상이다. IP 형식 검증은 발신자의 신원을 검증하지 않는다.
- 전역 IP 추출 변경은 SMS/email 인증 횟수의 Redis 키에도 적용된다. 이전에 IP 목록으로 만든 횟수 키와 새 단일 IP 키는 달라지며, 기존 횟수 키의 TTL은 24시간이다.
- DB 롤백 시 원본을 보존하기 위해 Redis 삭제를 커밋 뒤로 옮긴다. 그 대신 DB 커밋 후 Redis 정리 전에 중단되거나 정리가 실패하면 다음 실행에서 같은 집계를 다시 합산할 수 있다. 동기화 중 같은 키에 추가된 검색량의 유실까지 원자적으로 해결하는 변경은 아니다.
- 스케줄러가 동기화 전에 별도 트랜잭션으로 수행하는 기존 가중치·횟수 초기화 순서는 변경하지 않는다.
